◧ THE BOX · field manual
The full user story

A spare machine becomes a server that runs itself.

Running your own server is powerful, and almost nobody does it — because keeping one alive is a second job. The Box removes the second job. You point it at a machine you already have; it becomes a private server that's safe to change, hard to break, and able to look after itself.

Operator A — a person, using a dashboard
Operator B — an AI agent, using the same actions as tools

The same Box serves both. Everything below happens through one friendly front door for people and one machine-to-machine door for agents — the two doors do the same things. Here's the whole journey.

The journey · start to steady state

01

A machine you already have

Old laptop · mini-PC · Raspberry Pi · a rented VPS

No special hardware. If it can turn on, it can become a Box. The whole idea is to make cheap, idle, or already-paid-for compute useful without it becoming a hobby that eats your evenings.

02

It becomes a Box

Answer a few questions → the machine sets itself up

You don't install and configure an operating system. You answer a few plain questions in a small tool — the Configurator — like what to name it, your Wi-Fi, and who's allowed in. That produces a single orders file. The Box's standard image reads those orders on first boot and configures itself to match. No account required, and nothing you typed ever leaves your browser.

Operator A  Plug in a prepared USB stick (or run one command) and walk away; a few minutes later the machine is a Box.

Operator B  An agent does the same unattended — and can turn a whole list of machines into Boxes in one pass.

Why it holds up  One identical image for every machine, personalized only by the orders file. One Box or fifty is the same amount of effort.

03

First contact

A private dashboard shows up on your network

The Box comes up at box.local with a dashboard — the same Configurator look. It's private by default: only you, on your own network, can reach it. Nothing is exposed to the internet until you choose to expose it.

Operator B  An agent connects to the same Box through its machine interface and sees the same controls, as tools it can call.

04

You put something on it

Pick a template, or say what you want in plain English

Choose a template — a website today; a photo library, a notes API, a database as the catalog grows — or just describe what you want. The Box builds it and turns it on. You never see the machinery underneath.

Operator B  An agent calls one action, "deploy this," and gets back a working service it can start using immediately — its own durable place to keep state and run things.

Status  Working today for static websites; more templates are next.

05

You make it public

A tunnel carries traffic in — your home network stays closed

By default your Box is private. To put a service on the internet, you don't open risky holes in your home router. You connect a tunnel — the free way is pasting one token from Cloudflare — and the Box routes your chosen web address to your service. Traffic comes in through the tunnel; your network stays shut. Your dashboard stays private even while your website is public.

Paid option  Skip the setup entirely and let us hand you a web address and carry the traffic. That's the paid tier — and the free path never depends on us.

06

You can't really break it

Every change is a snapshot · a bad one undoes itself

Before any change takes effect, the Box saves the whole machine's state as a labeled snapshot. After the change, it checks that everything still works — and if something's wrong, it flips itself back to the last good snapshot automatically. You can also roll back to any earlier snapshot with one click. Mistakes are cheap, and "I broke my server" mostly stops being a thing that can happen.

Why it holds up  This is the heart of the product: safety isn't a feature you turn on, it's how every change already works.

07

It keeps itself current

Updates its own core software, like a phone OS update

The Box can update its own platform: it fetches the new version, installs it, confirms the machine comes back healthy, and undoes the update by itself if anything's off. You can let it do this on a schedule, or pin it to a specific version you trust.

Why it holds up  An update is just another snapshot — so the same safety net that catches a bad change catches a bad update.

08

More than one

Several Boxes find each other and show up as one map

Own a few Boxes and they discover each other on your network and appear together in a single view — which are healthy, which are public, what each one is running. Seeing a Box on the map doesn't grant control; you pair with one to actually manage it. Look is public-ish on your LAN; touch requires permission.
