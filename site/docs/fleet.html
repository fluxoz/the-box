Guide

Running a fleet

More than one Box? They find each other and you manage them from one place, with no central controller and no box trusting another. There's only one thing every Box trusts: you.

Discovery

Every Box announces itself, and each Box discovers the others directly and reads their coarse health (peer-federated, no registry). Two planes:

  • LAN: over mDNS, for Boxes on the same network. Zero config.
  • Mesh: over a shared Box Connect tailnet, so a fleet spans sites, not one LAN.

Open any Box's dashboard → Fleet to see the others and their health. Discovery is not authorization: seeing a Box reveals only a coarse health summary.

Manage the fleet

The Fleet view links straight into each peer's dashboard. Because Boxes trust you and not each other, you pair (or SSH-tunnel) with each Box you manage. No box acts on another's behalf, so a compromised Box can't reach into its neighbours.

A Box's session is scoped to that Box. Pair each one from your browser; revoke any device from a Box's Devices page.

Batch installs

One generic image serves every machine, and identity arrives at first boot. So provisioning many Boxes means handing each a different orders file: per-machine hostname, your SSH key, and a one-time pairing code. Install them the same way you install one.
