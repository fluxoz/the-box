Guide

Running a fleet

More than one Box? They find each other and you manage them from one place, with no central controller and no box trusting another. There's only one thing every Box trusts: you.

Discovery

Every Box announces itself, and each Box discovers the others directly and reads their coarse health (peer-federated, no registry). Two planes:

  • LAN: over mDNS, for Boxes on the same network. Zero config.
  • Mesh: over a shared Box Connect tailnet, so a fleet spans sites, not one LAN.

Open any Box's dashboard → Fleet to see the others and their health. Discovery is not authorization: seeing a Box reveals only a coarse health summary.

Manage the fleet

The Fleet view links straight into each peer's dashboard. Because Boxes trust you and not each other, you pair (or SSH-tunnel) with each Box you manage. No box acts on another's behalf, so a compromised Box can't reach into its neighbours.

A Box's session is scoped to that Box. Pair each one from your browser; revoke any device from a Box's Devices page.

Batch installs

One generic image serves every machine, and identity arrives at first boot as orders. For a fleet, build one set of orders with the name on Auto-assign: every machine takes the same orders, derives its own stable name (box-3f2a1b), and the one pairing code claims each Box. Three deliveries, same result:

  • Network boot (PXE) — the fastest way to do twenty machines; see below.
  • One USB stick, many machines — a personalized flash image isn't consumed by installing: boot the same stick in each machine in turn.
  • The one-liner — machines already running Linux take the pasted curl | sh command, e.g. over SSH in a loop.

Provision over the network (PXE)

Build your orders in the Configurator and open Provisioning a fleet? — it emits one command:

curl -fsSL https://thebox.build/pxe.sh | sudo BOX_ORDERS_B64='<yours>' sh

Run it on any Linux machine on the same network (a laptop is fine — this machine is not wiped, it becomes the depot). It fetches the installer once, verifies it against checksums pinned in the TLS-served script, and serves it to the LAN. Then network-boot each machine you want to convert — pick PXE in the boot menu, or put network first in the boot order on blank machines. Each one wipes itself, installs Box OS unattended, and comes up as its own Box. Stop the depot with Ctrl-C when the fleet is up.

Every machine you network-boot while the depot runs is erased. The depot answers only machines that ask to netboot (proxy DHCP — your router keeps assigning addresses, and nothing already booted from its own disk is touched), but the machine at the boot menu is past its last prompt: the orders carry your consent, so the install runs to completion.

Details: the depot answers firmware PXE (BIOS and UEFI) with an iPXE chainloader over TFTP; iPXE fetches the kernel and initrd from the depot over HTTP with your orders riding the kernel command line, RAM-only. Each machine still fetches the Box OS closure from the binary caches, so the LAN needs internet. Have PXE infrastructure already? The same panel saves a boot.ipxe: put it beside the release's bzImage, initrd and netboot.ipxe on your boot server and point your DHCP at it.
