Guide

Install

The Box is a blow-away install: one generic appliance image wipes the target and takes it over. The machine's identity — hostname, keys, Wi-Fi, disk layout — arrives at first boot, so the same image serves every machine.

It wipes every disk. The installer only proceeds after you confirm, but there is no dual-boot and no going back. Use a spare machine, a fresh VPS, or a VM.

Linux & VPS — the one-liner

On any running Linux machine (a spare PC, or a fresh cloud VPS):

curl -fsSL https://thebox.build/install.sh | sudo sh

It fetches the installer, kexecs straight into it (no reboot menu, no BIOS fiddling), wipes the disks, lays down Box OS, and reboots into a running Box. On a 4 GB VPS the whole thing takes a few minutes.

Every artifact it fetches is checksummed against SHA256SUMS before anything is executed.

Bring your settings — the Configurator

By default the installer asks you to decide on the box. To set things up ahead of time instead, use the Configurator — a browser tool that builds your Box's orders (name, disk choice, your SSH key, Wi-Fi, a Cloudflare tunnel token, and a one-time pairing code). Nothing is sent anywhere: the orders stay in your browser, and you paste them into the command:

curl -fsSL https://thebox.build/install.sh | sudo BOX_ORDERS_B64='<paste>' sh

The orders ride base64 on the command line, so there's nothing to download or move. The pairing code's hash travels with them, so the Box is pairable from first boot — you never need SSH. Keep the code (and any generated SSH key) in your recovery kit.

The Configurator warns you when your orders carry a secret (a Wi-Fi password or a tunnel token), so you know to treat the command like a password.

Or decide on the box

Skip the orders and the installer drops into a short console wizard with the machine's real disks in front of you: pick a layout — single, mirror (two disks, redundant), or pool — confirm, and it installs. Good for a machine you're sitting at.

Windows

In an elevated PowerShell:

irm https://thebox.build/install.ps1 | iex

This stages the installer's kernel and initrd onto the Windows disk, adds a one-time boot entry, and reboots into the installer, which then wipes and installs. As with Linux, it takes the whole machine.

macOS

A Mac can't be taken over in place. Run a Box where it belongs — on server hardware — and drive it from your Mac's browser:

  • A cheap VPS — run the Linux one-liner inside the VPS.
  • A local VM — UTM or QEMU, boot the installer ISO, install into the VM's disk.

Bare metal — no OS to take over

If the machine has no running OS to launch the one-liner from, boot the installer directly:

  • Network boot (PXE): point the machine's PXE/iPXE at the release's netboot.ipxe (it chain-loads the kernel + initrd). The artifacts are on the latest GitHub release.
  • ISO: build the installer image and write it to a USB stick: 
    nix build github:fluxoz/the-box#installer-iso
sudo dd if=./result/iso/*.iso of=/dev/sdX bs=4M status=progress conv=fsync
    Boot it, and it runs the same disk wizard.

The netboot.ipxe, kernel, and initrd are published on each release, not on this site — Pages isn't the place for large binaries.
