Guide

Install

The Box is a blow-away install. One generic appliance image wipes the target and takes it over. The machine's identity (hostname, keys, Wi-Fi, disk layout) arrives at first boot, so the same image serves every machine.

It wipes every disk. The installer only proceeds after you confirm, but there's no dual-boot and no going back. Use a spare machine, a fresh VPS, or a VM.

Linux & VPS

On any running Linux machine (a spare PC, or a fresh cloud VPS):

curl -fsSL https://thebox.build/install.sh | sudo sh

It fetches the installer, kexecs straight into it (no reboot menu, no BIOS fiddling), wipes the disks, lays down Box OS, and reboots into a running Box. On a 4 GB VPS the whole thing takes a few minutes.

Every artifact it fetches is checksummed against SHA256SUMS before anything is executed.

Bring your settings: the Configurator

By default the installer asks you to decide on the box. To set things up ahead of time instead, use the Configurator. It's a browser tool that builds your Box's orders: name, disk choice, your SSH key, Wi-Fi, a Cloudflare tunnel token, and a one-time pairing code. Nothing is sent anywhere. The orders stay in your browser, and you paste them into the command:

curl -fsSL https://thebox.build/install.sh | sudo BOX_ORDERS_B64='<paste>' sh

The orders ride base64 on the command line, so there's nothing to download or move. The pairing code's hash travels with them, so the Box is pairable from first boot and you never need SSH. Keep the code (and any generated SSH key) in your recovery kit.

The Configurator warns you when your orders carry a secret (a Wi-Fi password or a tunnel token), so you know to treat the command like a password.

Or decide on the box

Skip the orders and the installer drops into a short console wizard with the machine's real disks in front of you. Pick a layout (single, mirror for two redundant disks, or pool), confirm, and it installs. Good for a machine you're sitting at.

Windows

Build your command on the front page or in the Configurator, then paste it into an elevated PowerShell. It looks like this, with your orders riding base64 inside it, exactly like the Linux one-liner:

$env:BOX_ORDERS_B64='<yours>'; irm https://thebox.build/install.ps1 | iex

This stages the installer's kernel and initrd onto the Windows disk, adds a one-time boot entry, and reboots into the installer, which then wipes and installs, unattended start to finish. As with Linux, it takes the whole machine. A bare irm | iex with no orders refuses to run.

Mac

A Mac mini or an old MacBook makes a quiet, low-power Box. To the Box, a Mac that already runs Linux is just a Linux machine, so the one-liner works on it. The two kinds of Mac get there differently:

  • Intel Macs are ordinary x86 PCs. Run the Linux one-liner on top of an existing Linux install, or boot the installer from a USB stick (see Bare metal). The 2018 models have a T2 chip: you first allow booting non-Apple systems in recovery, and Linux support for that hardware takes extra kernel bits.
  • Apple Silicon (M1/M2) boots Linux through the Asahi project. Install Asahi Linux first (it sets up the bootloader and lives beside a small macOS stub that Apple requires on these machines), then convert that Linux install into a Box. This path is experimental and tracks Asahi's hardware support: M1 and M2 are solid, M3 is in progress, M4 isn't ready yet.
A Mac can't boot an arbitrary USB image the way a PC does, so there's no blow-away Apple-Silicon image. The Box rides on the Linux that Asahi installs.

Bare metal: no OS to take over

The normal answer is the flash door on the front page: pick PC · laptop · mini-PC, download your image, write it to a USB stick, and boot the machine from it. Your orders are inside, so the install runs unattended and the Box comes up already yours. This is also the path for an Intel Mac with no OS on it. Two more ways for special cases:

  • Network boot (PXE): for many machines at once — one command turns a spare Linux machine into a PXE depot serving the installer with your orders, and every machine you network-boot converts itself. Build it in the Configurator's fleet panel; details in the fleet guide.
  • Decide on the machine: flash the plain (unpersonalized) thebox-x86.img.xz from the release — its hash is published, so you can verify it — and boot it. With no orders inside, it runs the setup wizard on the machine's own screen and in a browser, and touches nothing until you commit.

The netboot.ipxe, kernel, and initrd are published on each release, not on this site. Pages isn't the place for large binaries.
