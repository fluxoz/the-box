Concepts

How it works

Four ideas explain the whole thing: it's an appliance, everything is a generation, the box reconciles itself, and it's sovereign by construction.

The appliance model

There is one generic Box OS image. It carries no machine-specific state: no hostname, keys, or disk layout baked in. That state arrives at first boot as a small handoff (from the Configurator or the console wizard). So the same image installs every machine, and "provision a hundred Boxes" means "hand out a hundred handoffs." Installing wipes the disk and takes the machine over. No dual-boot, no drift.

Atomic generations

Every change (adding a service, a platform update) is built into a new, complete system generation and switched to atomically. Nothing is edited in place. That means you can roll back to any previous generation instantly, and a change that doesn't come up healthy rolls itself back. Config is the source of truth; the running system is derived from it, reproducibly.

Self-reconcile

A Box builds its running system from its declarative config: the config compiles to a system definition, which builds a generation, which the Box switches to and health-checks. A platform update is the same loop with a newer channel pin. There's no central controller pushing changes. Each Box pulls its channel and reconciles itself.

Sovereign by default

No account, no phone-home. Your keys and secrets are generated in your browser or on your Box and never leave: the pairing code, SSH keys, and the backup key are yours alone, which is also why only you can recover them. Backups are client-side encrypted, so storage providers see only ciphertext. Remote access is a mesh you control, or a tunnel you bring. The paid tiers are operated services (offsite storage, a managed relay), never a gate on the software. The software is all free and open.
