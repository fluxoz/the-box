Guide

Agents

Plug a spare machine into your network and have an agent turn it into a Box and run it for you — provision, configure, maintain — hands-off. A Box is built to be driven by software, not just a browser.

Provision: bare machine → Box

If the spare machine has an OS you can SSH into, one command turns it into a Box:

boxd provision root@192.168.1.42 --ssh-key ~/.ssh/id_ed25519.pub

That single command:

  1. mints the machine's identity — a hostname, your SSH key, and a one-time pairing code (only its hash ever leaves the command);
  2. ships it over SSH as install orders and runs the takeover installer, which wipes the disk and boots the Box OS;
  3. waits for the machine to come back up as a Box;
  4. redeems the pairing code for a session token and prints it.
Takeover wipes the disk. The orders carry explicit erase_disk consent and the installer refuses to touch a disk without it — but point provision at a machine you intend to convert, not your daily driver.

For a machine with no OS (bare metal, blank disk), there's nothing to SSH into yet — flash the installer or boot it over the network first (see Install → bare metal and Raspberry Pi). Once it's a Box, everything below is the same.

Machine-readable output

Add --json and the command prints exactly what an agent needs to take over:

boxd provision root@192.168.1.42 --ssh-key ~/.ssh/id_ed25519.pub --json
{
  "address": "192.168.1.42:2693",
  "token": "…",
  "mcp_url": "http://192.168.1.42:2693/mcp",
  "dashboard": "http://192.168.1.42:2693/"
}

Useful flags: --hostname (defaults to a stable per-machine name), --layout single|mirror|pool, --reach-host (if the Box's address differs from the SSH target), --ssh-opt (passed through to ssh, e.g. -p 2222).

Configure & maintain over MCP

Every Box runs an MCP server at /mcp (JSON-RPC 2.0 over HTTP). It's the same declarative surface the dashboard and CLI write, so an agent manages a Box the same way you would. Authenticate with the session token as a Bearer header:

Authorization: Bearer <token>

The tools an agent can call:

AreaTools
Deploylist_templates, deploy, deploy_static_site, delete_service
Inspectget_status, list_services, list_generations, list_history
Maintainrollback, channel_status, channel_check
Backupsbackup_status, backup_snapshots, backup_now, backup_restore
Deploys are atomic Nix generations, and any generation can be rolled back — so an agent can change things confidently: a bad deploy is one rollback away, and a failed platform update rolls itself back. See How it works.

Who the agent is

An agent is just another operator device. Its token is a normal session: it appears in the Box's Devices list and you can revoke it there at any time. The Box trusts you (and the keys and codes you hand it) — never another machine on its own authority. Give an agent its own SSH key and its own session so you can retire it independently.

Already have a Box and want to hand an agent a session without provisioning? Run boxd auth mint --label agent on the Box and give the agent the printed token.
